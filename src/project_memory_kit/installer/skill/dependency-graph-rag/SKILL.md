# Dependency Graph RAG

Use the already installed PMEM for this exact configured project root. MCP
must serve the same `.project-memory/` as `./pmem`; config text alone is not a
live connection. Never initialize/index a neighbour or parent directory, use a
legacy Tencent backend, expose secrets or change trust to answer a memory query.

Use PMEM for documents, working state, durable findings and decision evidence.
The configured GitNexus provider owns code symbols and dependencies. Resolve
the exact bound repository ID with `./pmem code`; use the installed code tools
or that repository's GitNexus index for query/context/impact/detect-changes.
Shared binaries and registry do not merge project databases. PMEM document
refresh and GitNexus code refresh are separate operations; stale/unavailable
code coverage is explicit. Preserve repository identity/revision in code links.
Memory context stays bounded and memory-only by default. Request code evidence
only for a concrete gap through `./pmem code search --repository <ID> --query
<text>` or context `--include-code` / MCP `include_code: true`. Unsupported
HTML/CSS may remain explicit text material without a duplicate native graph.

For meaningful work read one bounded `pmem_context` or CLI context and relevant
sources, or reuse current same-task evidence. Reset only for a new task. Retrieve
more for a specific gap; degraded/empty/lexical fallback is not absent knowledge
or confirmed semantic success. A typo/status exchange needs no new cycle.

Refresh stale/changed indexed inputs once when needed; doctor is for setup or
malfunction. Impact/test selection follows an actual coverage gap. Verify affected
contracts and reuse matching green evidence; no automatic command sequence,
audits, watcher or full suite.

Save changed durable findings in knowledge and reasons/alternatives in rationale.
Read existing records before update/add; verify saved/completed ID/version with
show/search. Queued/busy remains pending. Preserve locks, privacy, user files and
project forks; do not edit SQLite or require a Git commit for local persistence.

Open only the relevant section when an operation needs detail:

- [Operations and safeguards](references/project-memory-protocol.md): setup,
  context/retrieval, writes/locks, failures, derived Human views and exact command syntax.
- [Technical task reference](references/task-workflow.md): affected relationships,
  installed schema/CLI examples and task handoff details.

These are conditional references, not a second required startup/checklist. Local
selected project workflows remain authoritative. Report actual evidence, memory
updates or pending owner, and any remaining limitation in the current handoff.
